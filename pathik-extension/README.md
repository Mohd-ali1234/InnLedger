# Rooms Booking → Pathik autofill

Turns **Save on Pathik** in the booking app into a single click: Pathik's
*Add Guest* form opens in a new tab with the booking already typed in.

It exists because a web page cannot write into another site's form — the browser
blocks cross-origin access. An extension is allowed to run on both pages, so it
can carry the booking across.

**It never submits.** It fills the fields, highlights them, and stops. You check
the form, add what Pathik still needs, and click Submit yourself.

## Install (Chrome or Edge, one time)

1. Open `chrome://extensions` (Edge: `edge://extensions`).
2. Turn on **Developer mode** — top-right toggle.
3. Click **Load unpacked** and pick this `pathik-extension` folder.
4. Reload the booking app tab.

The **Save on Pathik** dialog now shows **Open Pathik & fill** instead of the
console instructions.

To confirm it is active, the app page will carry a `data-pathik-bridge="1"`
attribute on `<html>`.

## Using it

1. Log in to Pathik in the same browser.
2. In the booking app, open any booking's **⋯** menu → **Save on Pathik**.
3. Check the date format matches Pathik's date picker.
4. Click **Open Pathik & fill**.
5. On the Pathik tab, fill in what the app does not hold — date of birth,
   check-in/out times, document type and number, document images, coming
   from / going to — then review and **Submit**.

Fields worked out from the free-text address (locality, city, district, zip,
state, country) are marked amber in the app. Read them before submitting.

## How it works

| File | Runs on | Job |
| --- | --- | --- |
| `bridge.js` | the booking app | Marks the page as extension-enabled; relays the booking to the worker |
| `background.js` | service worker | Holds the booking in session storage, opens Pathik's Add Guest tab |
| `fill.js` | Pathik Add Guest | Collects the booking, waits for the form, injects the filler |
| `page-fill.js` | Pathik page context | Writes the values in and refreshes the bootstrap-select dropdowns |

`page-fill.js` runs in the page's own context rather than the extension's
isolated one, because Pathik's country and state dropdowns are
bootstrap-selectpickers that only redraw when the page's own jQuery refreshes
them. Country is set first, then the state dropdown is polled for up to 8
seconds while Pathik reloads it over AJAX.

The booking is stored only in `chrome.storage.session`, is deleted the moment
the Pathik tab collects it, and never leaves your browser.

## Changing the app's address

`manifest.json` matches the dev server on `localhost:5173` and `127.0.0.1:5173`.
If you serve the app somewhere else, add that origin to the first
`content_scripts.matches` entry and reload the extension.

## Firefox

Firefox needs an `applications.gecko.id` key in the manifest and loads unpacked
extensions through `about:debugging` → *Load Temporary Add-on*, which resets on
restart. The console-paste script in the app works there with no install.

## Keeping it in step

`page-fill.js` mirrors the console script generated by `buildAutofillScript()`
in `frontend/src/utils/pathik.ts`. Field mapping lives only in `pathik.ts` — the
extension is a dumb filler and does not decide what goes where. Change the
mapping there.
